# Git-hooks template

Reusable native git-hook scaffold that enforces the `/core:commits` commit
schema, ticket traceability (via branch name, optionally via extension map),
and an opt-in protected-branch pre-push guard.

Install via the `/core:githooks-install` skill. Manual install is possible
but not the expected path.

## Layout

```
githooks-template/
├── commit-msg                   # delegator — runs validate-commit-subject.sh
├── pre-push                     # validates push-range subjects; optional guard
├── validate-commit-subject.sh   # subject format + ticket traceability
├── config.sh.example            # all project-specific knobs
└── modules/
    ├── extension-ticket-map/    # opt-in: per-package ticket enforcement
    └── protected-branch-guard/  # opt-in: custom pre-push guard
```

## Enforced checks

- Commit subject format: `[TYPE] TICKET (scope) summary`.
- Merge commits are exempt from subject policy.
- `Revert "..."` subjects are exempt.
- When `HOOK_REQUIRE_TICKET=1` (default): ticket in subject MUST match the
  ticket derived from the branch name. If the extension-ticket-map module is
  enabled and the commit touches mapped packages, that map takes precedence;
  mixed-package commits with conflicting tickets are rejected.
- `pre-push` re-validates subjects of commits in the push range (skipping
  merge commits and commits already present on any remote).
- When `HOOK_PROTECTED_BRANCH_GUARD=1`: pre-push additionally invokes the
  configured guard command for pushes to protected branches.

## Activation

The template is typically activated via the `/core:githooks-install` skill.
It uses the same pattern as FEIN: tracked source under `.githooks/`, runtime
enforcement via a local hooks dir pointed to by `core.hooksPath`.

```bash
HOOKS_DIR="$(git rev-parse --path-format=absolute --git-common-dir)/hooks-local"
mkdir -p "$HOOKS_DIR"
cp .githooks/* "$HOOKS_DIR"/
chmod +x "$HOOKS_DIR"/commit-msg "$HOOKS_DIR"/pre-push "$HOOKS_DIR"/*.sh
git config core.hooksPath "$HOOKS_DIR"
```

After any change to `.githooks/`, resync into `$HOOKS_DIR`.

## Configuration

All project-specific values live in `config.sh` next to the hooks. The file
is generated by the install skill; `config.sh.example` documents every knob
and the defaults.

Defaults match the `/core:commits` schema and a typical single-package repo
with branch-name ticket traceability. Enable modules via config flags.

## Emergency bypass

Set the env var named by `HOOK_BYPASS_ENV` (default `SKIP_COMMIT_MSG_CHECK`)
to `1` for a one-off commit that skips all validation:

```bash
SKIP_COMMIT_MSG_CHECK=1 git commit -m "..."
```

Use sparingly. The bypass only covers `commit-msg`; pre-push is not bypassed.
